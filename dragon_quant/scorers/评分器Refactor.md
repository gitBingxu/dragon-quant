# 五维「识别真龙」评分规范

本文描述当前 `scan` 的实际执行规则，不再作为新旧评分器并存的迁移草案。范围仅限龙头识别，不包含买卖点、账户交易或未来收益预测。

## 一、识别目标与边界

龙头不是预判出来的，而是根据已经出现的盘面证据识别出来的。四大特征必须同时达标，资金承接只作补充证据。

- 当前只有 `dragon_quant/scorers/` 一套评分器；`scan_v2` 是 `scan` 的兼容入口，没有新旧算法开关。
- SQLite 继续沿用 `*_v2`，扫描 ID 保持 `v2_YYYYMMDD_topN`；旧 `*_v1` 仅供显式历史查询。
- 板块使用同花顺行业板块 `/thshy/`、`/hyzjl/`，代码为 881xxx，不是概念板块 `/gn/`。
- 默认盘后扫描。`--force` 可用于测试盘中数据，但所有“封至最后一分钟”仅代表已取得的分钟数据，不能预知收盘。
- 分时和盘口是采样证据，无法证明逐笔封板稳定性或真实资金流向；“带动”“虹吸”表示规则识别的时序关联，不是已证实的资金因果关系。

## 二、数据准备与模块契约

### 扫描流程

| 阶段 | 执行规则 |
|---|---|
| A | 读取行业排行，过滤黑名单；领涨 Top5 用于候选，领跌 Top20 用于承接对手盘 |
| B | 每个领涨行业最多拉取前五页、约 50 只成分股；从实际取得样本中选取涨幅 ≥9.9% 的主板股票，排除 ST、双创、北交所，按代码去重 |
| C | 拉取候选日 K，计算 `board_count` 和 `fived_pct`；五日涨幅为最新收盘价相对前五个交易日收盘价的累计收益；不足六根有效日 K 时为 0 |
| D | 预填全部候选分钟线、板块分钟线、上证分钟线及十日板块五分钟线；成分股行情代码排序后每批最多 200 只顺序获取、合并，不截断总数 |
| E | 五维评分、四维门槛及异常检查，生成 `DragonVerdict` |
| F | 保存全部诊断结果，仅通过者获得真龙排名；Top N 真龙展示和入库，应用原有五日去重 |

主板候选池包含实际采到的行业涨停股，不保证覆盖行业所有成分股。板块共鸣、换手相对分位均是这一成分股样本的统计，不应表述为全行业无遗漏统计。

### cache 数据契约

评分器是只读 cache 消费者，统一入口 `score(code, cache, **kwargs) -> ScoreResult`，不调用 Provider、不发网络请求。

| 数据 / cache 键 | 类型与来源 | 消费方 |
|---|---|---|
| `sector:components:{sector}` | `list[StockInfo]`，同花顺行业成分股 | drive、liquidity、编排器 |
| `kline:day:{code}` | `list[KBar]`，雪球日 K | 编排器计算连板、五日涨幅 |
| `kline:1min:{code}` | `list[KBar]`，雪球候选股当日分钟线 | drive、anti_drop、liquidity |
| `kline:1min:SH000001` | `list[KBar]`，雪球 `get_minute_kline("SH000001")` | anti_drop 大盘基准 |
| `kline:1min:sector:{sector}` | `list[KBar]`，同花顺 `/v6/time` 原始分钟点位 | drive、anti_drop |
| `kline:5min:sector:{sector}` | `list[KBar]`，同花顺 `/v6/line/48_{inner}/30/last1000.js` 的真实 OHLC，最近十个交易日 | absorption |
| `quotes:batch` | **`list[Quote]`**，腾讯行情与收盘盘口；评分器内部再构造代码字典 | drive、liquidity、持久化 |
| `Candidate.board_count/fived_pct` | Phase C 计算，通过 `candidate_pool` 参数传入 | leadership |
| `__meta__:sector_codes` | 扫描日领跌 Top20 行业代码，亦显式传入 `all_sector_codes` | absorption |
| `__meta__:sector_name_map` | 板块名称字典，编排器显式传入评分器 | 报告展示 |

**指数与股票必须区分：**裸代码 `000001` 正常解析为平安银行 `SZ000001`；上证指数必须显式请求 `SH000001`，且使用独立 cache 键。旧 `kline:1min:000001` 缓存不能作为指数读取。

**历史边界：**drive、anti_drop、liquidity 使用当日分钟或快照；leadership 使用历史日 K 派生的连板与五日收益，但自身不读取日 K；absorption 使用最近十个交易日五分钟线。

### 公共计算规则

- 分钟轴按 `timestamp // 60000` 对齐，取两序列时间点并集，同一交易时段内允许单序列缺点前向填充；时段开始前没有数据则为 `None`。
- 当双方都缺分钟、跨午休或跨交易日时，分割窗口，禁止把间隔拼成连续几分钟；不跨时段前向填充。
- 时间与交易日划分固定 UTC+8，不依赖运行机器时区。
- 归一化涨幅直接使用 Provider 已按昨收计算的 `KBar.pct / 100`，不把首分钟价格当昨收。
- 价格达到涨停的采样容差为 `abs(price-limit_up) <= limit_up × PRICE_TOLERANCE`，默认 `PRICE_TOLERANCE=0.001`。
- 所有权重、业务阈值和降级分集中在 `registry.py`；浮点比较 epsilon 仅作数值误差容忍。

## 三、聚合、排名与持久化

| 维度 | 权重 | 最低门槛 |
|---|---:|---:|
| 带动性 drive | 0.30 | 40 |
| 领涨性 leadership | 0.25 | 40 |
| 抗跌性 anti_drop | 0.15 | 35 |
| 流动性 liquidity | 0.20 | 35 |
| 资金承接 absorption | 0.10 | 无 |

1. 四大特征任一低于门槛，或任一执行异常，`is_true_dragon=False`，记录 `reject_reason`。异常维度记 0 分用于诊断，不以 50 分兜底通过。
2. 资金承接无信号、数据不足或异常，给中性 50 分，标记 `fallback` 及原因，不获得否决权。
3. 所有候选仍计算五维加权综合分，以便诊断；**否决票综合分不是入选资格**。
4. `rank_verdicts()` 只对通过者按综合分降序排名，同分按股票代码升序；否决者 `rank=None`。
5. `raw_output.ranking` 为全部候选，按诊断综合分降序排列；`scan_stocks_v2` 保存全部明细及显式真龙 rank。
6. `--top N` 指最多展示和选入 N 只真龙，而不是强行补足 N 只候选。`dragons_v2` 只由通过者 Top N 贡献，五日去重后可少于 N 只，保留去重前排名。
7. 首次输出和缓存输出均只展示 Top N 真龙；无真龙时明确提示，仍保存扫描、否决原因与明细。
8. 历史重建只接受非明确否决、rank 非空且不超过原扫描 Top N 的贡献，保留旧记录未提供真龙标记的兼容语义。

评分修复不会自动重算或清除历史记录。需要按新规则重新扫描时，在盘后执行 `python -m dragon_quant scan --force --no-cache`；`--force` 跳过结果缓存，`--no-cache` 刷新 Provider 缓存。旧扫描结果仍代表生成时的算法和数据。

## 四、带动性 Drive

文案依据：“观察哪支股票最先涨停并稳定封死”“个股拉升后同板块跟随”。

`Drive = 0.40 × s_early + 0.35 × s_lead + 0.25 × s_voice`。

### 4.1 稳定封板最早

- 稳定封板时点定义为：**最后一次分钟收盘离开涨停后，持续封至最后有效分钟的连续封板段起点**。中间炸板后回封，按最后回封点而非首次触板排名。
- 比较池为同板块成分股中、属于现有主板涨停候选池的股票，含本股；不把已过滤的双创等额外加入。
- 有效行情与分钟线可识别稳定封板者参与排名；记录预期样本数、有效封板池大小、缺失代码。
- 升序竞争排名 `r=1+更早封板的股票数`，同分钟并列。
- `n=1` 得 100；否则 `s_early=(1-r/n)×100`。
- 数据完整但最终未封住，得 0；本股分钟线或涨停行情缺失，得 `DRIVE_NEUTRAL=40` 并标记降级。其他比较样本缺失时仍按有效样本评分，但标记不完整。

### 4.2 脉冲匹配与方向

1. 对个股和板块分别计算三分钟净涨幅窗口。个股阈值 3%，板块阈值 0.3%。按净涨幅由大到小选择峰值，抑制相距不超过三根的邻近峰，避免同段上涨重复计数；同高峰优先较早窗口。
2. 动作起点取该窗口内第一根实际上涨的分钟，而非直接拿窗口左端点充当起涨时间。首分钟跳空达阈值可作为开盘脉冲；只有扫描起始段允许开盘脉冲。
3. 每个个股脉冲匹配一个尚未使用、起点相距不超过三分钟的最近板块脉冲，同距离优先较早板块动作。
4. 个股先动，板块在其起点后最多三分钟内上涨至少 0.3%，且个股启动前板块未提前上涨 0.3%，记一次 `lead_event`。
5. 板块先动，个股在三分钟内启动，记一次 `follow_event`；同分钟启动不判方向。
6. 每个脉冲最多归类一次，同一匹配不能同时加带动次数和跟风次数。

打分：无带动事件为 0；有带动时 `base=min(70+(n_lead-1)×10,100)`，跟风扣分 `min(n_follow×20,100)`，再加可选相关性奖励并截断至 [0,100]。

相关性奖励：只使用**开盘至首次分钟收盘触板之前**的收益差分；无触板时使用可得全日数据。每段连续时序内比较滞后 0～3 分钟的互相关，正滞后相关最高且 ≥0.5 时奖励 10 分，全天最多加一次。没有带动事件不奖励。

缺个股或板块分钟线、个股全程平线时，子项 40 分并标记“无法验证带动时序”。一字涨停也不虚构主动带动事件。

### 4.3 板块共鸣

对有腾讯行情的行业成分股样本计数：涨幅 ≥9.9% 为涨停，涨幅 **>3%** 为强势。

` s_voice=min(涨停占比/0.10,1)×60 + min(强势占比/0.30,1)×40 `。

无行情样本给 40 分降级；仅部分样本可得时使用有效分母，并记录缺失标记。

## 五、领涨性 Leadership

`Leadership = 0.50 × s_board + 0.50 × s_pct`。

- 同板块指 `primary_sector` 相同的候选，不混用板块名称和代码，不用默认五日收益为 0 的普通成分股充当样本。
- `s_board=clip(100-(板块最高连板数-本股连板数)×10,0,100)`。
- 五日收益样本按股票代码去重，降序竞争排名 `r=1+收益严格大于本股者数量`，`s_pct=(1-r/n)×100`。
- 单样本没有相对优势，`s_pct=0`，标记 `degraded`；不凭空补造同行样本。

## 六、抗跌性 AntiDrop

`AntiDrop = 0.60 × 上证基准分 + 0.40 × 行业基准分`；两基准复用同一算法。

### 跳水与稳住

- 同一连续时段内，基准三分钟净跌幅 <−0.5% 的窗口合并成跳水段 `[a,b]`，b 为段内最低点。
- 段内 `d_x=g_x[a]-g_x[b]`、`d_s=g_s[a]-g_s[b]`，`s_hold_seg=clip((1-d_s/max(d_x,epsilon))×100,0,100)`。
- 多段按基准跌幅加权平均为 `s_hold`。
- 无有效跳水段，基准维度为中性 65。个股或基准缺分时，同样给中性 65 并标记降级。

### 反弹确认

取最深跳水段最低点 b：

1. 必须有 b 后完整三分钟确认窗口，且不能跨午休、缺口或隔夜。
2. 基准在窗口内不能再创新低，且必须实际回升；没有反弹或数据不足，`s_rebound=0`，记录原因。
3. 个股在 b 前后三分钟内取最低值；相同最低值选择最后一分钟，避免平台最早点虚增领先。
4. 个股最低点之后必须实际上涨，且 b 后窗口内相对 b 的最大回升必须为正；全程横盘不拿反弹分。
5. `lead=clip(b-个股最低点,0,3)`；`amp=clip(个股b后回升/基准b后回升,0,2)`。
6. `s_rebound=(lead/3)×60+(amp/2)×40`；`基准维度分=0.60×s_hold+0.40×s_rebound`。

横盘抗跌仍由 `s_hold` 奖励，不重复伪装成“率先起飞”。

## 七、流动性 Liquidity

`Liquidity = 0.50 × s_turnover + 0.50 × s_seal`，不额外惩罚一字板。

### 换手充沛度

- 绝对分 `s_to_abs=min(换手率/15%,1)×100`。
- 相对分使用有效成分股报价、按股票代码去重，含本股；降序竞争排名 `s_to_rel=(1-r/n)×100`，n≤1 时为 0。
- `s_turnover=0.5×s_to_abs+0.5×s_to_rel`；样本不足或缺失时记录降级。

### 封单强度与稳定性

- 有效涨停需报价涨幅 ≥9.9%，且现价位于涨停价容差内。
- 只有有效涨停、买一价位于涨停价容差内、买一量与成交量均为正，才计算封单强度。
- `strength=Quote.bid1_volume/Quote.volume`，均为腾讯 gtimg 的“手”；`s_strength=min(strength/0.3,1)×100`。
- 非涨停时普通买一挂单不算封单，强度为 0；已涨停但有效盘口缺失，强度按 60 降级。
- 分钟收盘从封住变为未封住计一次开板；单根分钟有触板高点且收盘回落，也计一次。连续未再次触板的低价分钟不重复计数。
- 分时完整且从未触板，稳定性为 0。触板后按开板 0 / 1～2 / ≥3 次分别给 100 / 60 / 20 分。
- 分钟线或涨停价缺失，稳定性按 60 降级。
- `s_seal=0.5×s_strength+0.5×s_stable`。一字封死且封单大时可得满分封板质量；换手低仅客观影响换手子项。

盘口源已完成：腾讯 f[9] 买一价、f[10] 买一量、f[20] 卖一量、f[36] 当日成交量；不调用盘后返回空体的雪球 `pankou.json`。

## 八、资金承接 Absorption

### 事件范围

- 目标为候选主行业；对手盘为**扫描日领跌 Top20 行业**，剔除目标自身，不是全部行业，也不是每天重新选择领跌行业。
- 从目标数据取最近十个交易日，两方按五分钟 bucket 对齐；对手盘缺 K 不填充。
- 六根五分钟 K 构成一个 30 分钟窗口，必须同交易日、同上午/下午时段且相邻时间戳严格相差五分钟。六根收盘时间首尾差为 25 分钟，但覆盖六根 bar 的 30 分钟价格区间。
- 窗口收益取末根收盘相对首根开盘，避免把窗口前一根或隔夜跳空混入。

### 检测规则

1. 目标窗口涨幅 >0.3%，至少四根 `close>open`，第一次阳线为拉升起点。
2. 对每个对手行业分别评估同窗口、前移一根窗口。每个窗口都需连续，收益 <−0.3%。
3. 跳水起点取窗口内第一次 close 低于前根 close 的位置；首根与其 open 比较。不要求单根跌幅超过 0.5%，允许连续缓跌累计达标。
4. 每个行业独立满足：跳水不晚于目标拉升，同交易时段，间隔 ≤10 分钟。未满足者不进入数量、均跌或强度计算。
5. 同一行业两个窗口都有效只计一次，取跌幅更大的有效窗口；有效出逃行业数至少两个。
6. 目标持续性要求：`drawdown_ratio=(窗口最高收盘-末收盘)/(窗口最高收盘-首开盘)`，末收盘为最高时为 0；比例 ≤0.3。
7. 各滑动窗口独立作为事件，窗口可以重叠；多事件 bonus 仍按有效窗口数量计算，并有上限。

### 事件评分

- 拉升分量 `min(目标涨幅%/2,1)×100`。
- 出逃分量 `min(|出逃均跌%|×有效出逃数/5,1)×100`。
- 强度 = 两分量各 50%；广度 = `min(有效出逃数/max(有数据对手盘数,10),1)×100`；持续性 = `(1-drawdown_ratio)×100`。
- 单事件分 = 强度 40% + 广度 20% + 持续性 40%。
- 最终分 = 最高事件分 + 每多一个事件 5 分（bonus 上限 15），总分封顶 100。
- 无事件、对手盘不足或目标数据不足，统一 50 分，`fallback=True`、`event_count=0` 并记录原因。

## 九、模块与验证

| 模块 | 职责 |
|---|---|
| `base.py` | `DragonVerdict`、归一化涨幅、排名分位、时段边界、涨停价格比较 |
| `registry.py` | 权重、门槛、阈值、降级分、指数代码 |
| `drive.py` / `leadership.py` / `anti_drop.py` / `liquidity.py` / `absorption.py` | 五维独立评分 |
| `aggregator.py` | 评分异常处理、四维否决、诊断综合分、真龙排名 |
| `orchestrator.py` | Provider 预填、候选、排名接入、报告、Top N 真龙持久化 |
| `storage/db.py` | 保留表结构，保存显式 rank 与全部扫描明细，重建时过滤否决及超 Top N 贡献 |
| `logging/reporter.py` | 显示实际事件、评分异常及缺数据原因，不重新打分 |

回归测试使用合成行情和临时数据库，覆盖：指数/股票分离、完整批量行情、否决和无真龙、五日去重排名、回封与并列、时序事件互斥、局部峰、封板前 bonus、反弹确认、非涨停盘口、虹吸缓跌/逐板块因果/跨时段和缺 K。相关入口为 `tests/test_scorers.py`、`test_orchestrator_helpers.py`、`test_provider_cache.py`、`test_providers_parsing.py`、`test_storage.py`、`test_logging.py`、`test_cli.py`。

实现测试不代表真实行情有效性或未来盈利能力；需要真实盘面核验时另行运行扫描，不自动污染历史记录或真实账户。
