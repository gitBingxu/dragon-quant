# 现状策略基线（代码核实版）

> 择时与仓位调研的「现状基线」附件。逐条对照 `review_account/` 代码核实（非文档转述），
> 用于：① 调研结论的映射落点；② 消融/归因实验的改造点识别。
> 核实日期：2026-10-14，分支 feat/reviewa-account-op。

## 1. 候选池链路（含情绪温度断点）

```
prep 命令 → prep_snapshots.result_json = { sentiment, main_boards, candidates }
                                              │              │
                                              │              ▼
                                              │   market.collect_candidates()
                                              │   只读 snap["candidates"] → 回测/实盘候选池
                                              ▼
                                        sentiment.position_pct（0/0.3/0.5/0.8）
                                        ❌ 无任何消费者 —— 链路断点
```

- `prep.compute_sentiment()`（prep.py:23）：涨跌停家数 → `position_advice` 启发式四档（空仓 0 / 轻仓 0.3 / 正常 0.5 / 重仓 0.8）。
- **断点确认**：`market.py:45` 只取 `snap["candidates"]`；`sentiment` 键在 engine/strategy/execution 全文零引用。情绪→仓位链路「只产不用」。
- 快照缺失时回退旧逻辑：前 3 日全部真龙并集（`min_score=50` 过滤），此路径连 sentiment 数据都没有。

## 2. 买入规则（strategy.py）

| 买点 | priority | 触发时点 | 核心条件 | 分时依赖 |
|---|---|---|---|---|
| 分歧买龙 | 400 | 默认 10:00 | 上日前连续≥2 缩量一字；开盘<涨停×0.998；前 6 根 5 分 K 最低不破昨收、末根收盘≥首根开盘 | 强（缺分时跳过） |
| MA5 承接 | 300 | 开盘 | 上日成交额≥2亿、换手≥5%；开盘距 MA5 ≤+3%；缺口 (-3%,7%]；未封死涨跌停 | 无（日K可判） |
| 突破前高 | 200 | 首根5分K | 量能基础同上；开盘>上日最高、缺口[0,5.5%]、距MA5≤12%、上日换手8–35%、成交额≥5亿；首根5分K换手≥0.5% 带量确认 | 强（缺分时跳过） |

- 入场质量硬门槛（`max_avg_amplitude` / `max_return_3d` / `drawdown_5d_floor`）：**默认全部关闭（0）**，分歧买点不适用。
- 择优：priority 降序 → 五维综合分降序 → 代码；每日最多买 1 次，最多 5 持仓。
- 否决口现状：**无 veto 接口**。信号在 `engine.py:104` `evaluate_buy` 产出后直接进 `state.pending`——竞价否决等后续机制的自然插拔点在「信号产出 → 入 pending」之间。

## 3. 卖出规则链（evaluate_sell，代码顺序即优先级，命中即短路）

| # | reason_code | 触发 | 参数 |
|---|---|---|---|
| 1 | first_day_stop_loss / hard_stop_loss | 已完成K最低触及止损线 | 首日 -3.5%，此后 -5% |
| 2 | trailing_take_profit | 峰值浮盈≥8% 后收盘自峰值回撤≥3.5%，或 14:55 跌破 MA5 | activate=8, drawdown=3.5, ATR倍数可选（默认关） |
| 3 | profit_back_to_cost_take_profit | 峰值浮盈≥6% 后最低触及完整成本线 | activate=6，成本线含费用滑点 |
| 4 | high_open_7pct/5pct_no_limit_clear | 高开≥7% 首根5分K未触板；高开[5%,7%) 前6根未触板 | 分时依赖 |
| 5 | next_day_close_below_open / close_below_open_stop / break_intraday_ma_stop | 14:55 弱势（收<开且跌>1%或破MA5或破昨收）或收盘低于 MA5 | tolerance=1% |
| 6 | next_day_limit_up_half | 首个可卖日 14:55 仍封板且未减过仓 → 卖半 | next_day_half_enabled |
| 7 | volume_spike_take_profit | 14:55 累计量≥上日全天×1.3 且未封板 | spike=30% |

特点：止损 2 档、保护类 3 条（移动止盈/保本/弱势）、情绪类 2 条（高开窗口/放量）、减仓位 1 条。**全部硬编码，无单条开关**——消融实验需先加机制。

## 4. 仓位与成交（execution.py）

- `buy_quantity`：`budget = min(cash, equity × max_position_pct/100)`，默认 max_position_pct=100 → **单笔全可用现金**。
- `risk_per_trade_pct`（默认 0=关）：按首日紧止损+滑点+费用估算每股风险，反推数量上限——已是「固定风险比例」雏形，未验证推广。
- 费用：滑点各 0.2%、佣金 0.03%（最低 5 元）、卖出印花税 0.05%、100 股整手。
- 涨跌停不可成交建模：加滑点后越界不成交；涨停买不进、跌停卖不出。

## 5. 验证框架现状（evaluation.py）

- `compare_strategies`：60/20/20 时间划分，4 个固定 variant（baseline / risk_budget / entry_quality / adaptive_exit），训练+验证各≥10 笔且回撤≥-15% 才可被选，独立测试 + 双倍滑点压力测试，不自动改默认参数。
- `metrics` 产出：total_return / max_drawdown / trade_count / closed_count / win_rate / profit_factor_returns / fees / turnover / largest_win_share / open_positions。
- **无夏普/索提诺/卡玛比率**；无按 reason_code 的盈亏归因；无参数敏感度扫描；variant 集合写死，非声明式。

## 6. 数据约束对验证的硬性影响

- 雪球 5 分 K 仅约 14 天；2026-09-13 审计：2026-06-26~09-07 区间 51 个交易日中 **45 天日K兜底**（`data_quality=mixed`）。
- 兜底日：分时规则（分歧买龙、突破前高、高开窗口）自然跳过 → **这些规则在多月回测里基本无法被验证**，只能依赖近 14 天窗口或后续攒数据。
- 兜底日成交价为保守近似（止损线/成本线/收盘价），与严格盘中非同一精度。

## 7. 归因与消融的改造点（本次落地候选）

| 目标 | 现状 | 最小改造 |
|---|---|---|
| 按卖出原因归因盈亏 | trades 已带 reason_code，数据齐备 | 纯分析函数，聚合 trades/positions 即可，**零策略改动** |
| 单条卖出规则消融 | 规则链硬编码 | StrategyConfig 加 per-rule 开关（或规则表化），evaluate_sell 按开关跳过 |
| 参数敏感度扫描 | variant 写死 | compare_strategies 接受声明式 variant 网格，复用同一门槛逻辑 |
| 情绪→仓位接入 | sentiment 只产不用 | engine/market 传入当日 sentiment，buy_quantity 预算再乘 position_pct 系数 |
| 竞价否决预留口 | 无 veto 接口 | engine 买入信号入 pending 前过 `entry_veto(cfg, cand, row)` 钩子，默认放行 |

## 8. 已知风险（继承自既有约定）

- 回测是纸上撮合，不模拟排队与冲击成本；实时延迟与成交条件可使结果不同。
- 评分历史可能来自不同版本，不能重算后冒充当时已知信号。
- `evaluation` 覆盖不足返回 insufficient_data 时，不得宣称策略改进。
