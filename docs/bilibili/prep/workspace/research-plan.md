# prep 复盘升级调研计划

- 调研日期：2026-10-28
- 证据截止：2026-10-28
- 调研问题：如何将当前 `prep` 从“市场情绪 + 个股定性评级”升级为“可解释的逐股量化得分、独立建仓仓位建议，以及供 Agent 生成次日条件化操盘策略的结构化事实层”？
- 目标读者：产品决策者、后续技术方案与实现人员、消费复盘产物的 Agent Skill。
- 市场范围：中国 A 股；盘后 T 日复盘与 T+1 交易计划。
- 输出类型：Full report，并在调研后分别形成产品方案与技术方案。
- 风险等级：高（结论将影响交易决策与仓位表达；事实、推断、缺失数据必须严格区分）。
- 使用 deep-research 的理由：需综合 5 份方法论文档、两个代码仓库与多个外部数据源，形成可复用、可审查的决策文档。

## 已确认的产品边界

- 每只候选输出量化总分、维度分、原始因子、加减分与风险原因。
- 输出是否值得建仓及单票建议仓位（占总资产百分比），不做组合仓位统筹。
- 盘后结论是预备建议；次日竞价/盘中正负反馈决定建议是否生效。
- 输出情绪锚、主线、主线龙头及市场角色，定义正负反馈与应对动作。
- Agent 只组织策略，不编造数值，不推翻量化硬否决。
- 本阶段不写产品实现代码，不做账户组合优化或自动下单。

## 调研线程

### A. 方法论文档提炼
- 目标：逐份提取复盘流程、因子、维度、决策顺序、次日反馈与应对规则。
- 起点：`docs/bilibili/prep/*.md` 五份文档。
- 完成标准：逐文档结构化笔记 + 跨文档共识/冲突 + 可量化与主观项区分。
- 改变结论的证据：文档实际内容不支持当前归纳，或同一术语在不同文档中口径冲突。

### B. 当前实现与差距
- 目标：确认当前 prep 的资产、公式、评级、产物及 Skill/auction/review-account 消费边界。
- 起点：`docs/agent/prep-auction.md`、`review_account/prep/*`、`review_account/verdicts.py`。
- 完成标准：建立“现有能力 → 产品缺口 → 可复用边界”映射。
- 改变结论的证据：代码与模块文档不一致，以代码与测试为准。

### C. stock-ana 数据能力盘点
- 目标：盘点可复用的免费行情/页面/接口、认证要求、字段、时点与历史能力。
- 起点：`~/Repo/stock-ana/tools/stock-data-apis`、`backend/services`、`backend/routes`。
- 完成标准：数据源到目标因子的映射，注明直接接口/计算派生/渲染截图/登录态。
- 改变结论的证据：仓库仅有 UI 占位而无真实上游，或接口字段与命名不符。

### D. 外部数据源与自动化可行性
- 目标：验证方法论所需但当前缺失的数据能否自动获取，不限于 tmdx。
- 起点：公开数据源文档、stock-ana 已封装接口、公开网页与可渲染页面。
- 完成标准：每类因子给出来源候选、自动化方式、历史可重建性、登录/反爬/许可风险与置信度。
- 改变结论的证据：官方/页面证据表明字段不存在、需登录、无法稳定自动获取或禁止目标用途。

## 编排方式

Lead + 3 个研究 subagent（A/C/D），main 负责 B、关键证据复核、结论和最终综合。研究阶段 subagent 只交付资料与证据，不决定产品或技术方向。

## 最终交付

1. 调研报告：逐文档提炼、跨文档综合、现状对比、数据可得性矩阵。
2. 产品方案：完整信息架构、评分与仓位语义、次日反馈 playbook、Skill 输入输出、异常与降级体验。
3. 技术方案：架构、因子模型、采集与快照、评分/仓位/反馈引擎、数据质量、回测验证、迁移与实施阶段。
