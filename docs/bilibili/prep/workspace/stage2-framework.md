# 阶段 2 main 框架与任务包（prep 复盘升级）

## 1. 已确认目标与验收边界

- 每只详细复盘标的：T 日量化总分、维度分、原始因子、逐因子贡献、风险/缺失原因。
- 明确是否值得建仓及单票建议仓位（账户总资产百分比）；不做组合归一或账户级组合优化。
- 盘后输出为“预备建议”；T+1 竞价/盘中正负反馈决定生效、降档、取消或退出。
- 输出市场情绪锚、风险锚、主线、主线龙头与先锋/中军/容量/跟风等角色及关系。
- 给 Agent Skill 提供版本化结构化上下文，生成明日策略；Agent 不编造数值、不发明阈值、不推翻硬否决。
- 本阶段只交付产品+技术方案，不写产品实现代码。

## 2. 三条候选路径（研究自审 MAJOR 的处置）

| 路径 | 描述 | 评价 |
|---|---|---|
| A. 确定性证据图谱 + 角色评分 + 条件 playbook | 原始资产→市场/主线/角色→个股评分/仓位→T+1 状态机→Skill | **推荐**。可重放、可解释、兼容现有 prep，能把客观事实与 Agent 叙事分开。 |
| B. Agent/多模态主导复盘（非常规） | 直接给 Agent 行情截图、长图和文本，让模型判主线/打分/仓位 | 可作逻辑持续性与舆情补充，不应作为主链：数值血缘弱、结果不稳定、历史回测和硬风控困难。 |
| C. 单一大总分 + 静态买卖建议 | 把所有市场/主线/个股/风险因子混成一个公式 | 最简单，可作比较基线；但混淆时间、角色和数据置信度，难以形成正负反馈与执行计划，不推荐作为目标架构。 |

## 3. 核心产品取舍

1. **全量观察、分层详细评分**：市场/主线使用全市场与全部涨停；详细池=近 5 日真龙 ∪ T 日主线核心 ∪ 全市场正/负锚 ∪ 持仓关联。不能只对旧真龙评分。
2. **四种输出不混义**：市场状态、主线持续、个股 T 日复盘分、数据置信度分别表达。T+1 反馈是另一时点结果，不回写 T 日分。
3. **角色化评分**：龙头/先锋/中军/容量核心/补涨或跟风采用不同权重与上限；保留角色竞争者、判定证据与未知状态。
4. **个股总分可解释**：至少覆盖个股龙头质量、主线地位、涨停/封板质量、资金与流动性、筹码/位置、持续性/股性；市场环境和消息风险通过闸门、乘数或独立证据表达，避免重复计分。
5. **单票仓位三态**：数据不足=`null`；明确不参与=`0`；可准备建仓=`>0` 的比例。由分数档、市场状态、角色上限、风险与数据完整度决定；不跨标的归一。
6. **硬闸门先于仓位**：公告/监管/停牌/不可成交/关键数据缺失等给出 reason_code；可保留诊断分，但资格和仓位不能被高分解除否决。
7. **正负反馈相对角色预期**：T 日冻结预期基准，不用统一“高开好/低开坏”。反馈条件必须可观察、可计算、带时点和 Unknown。
8. **主观逻辑单独成证据**：题材故事、社会传播、消息是否兑现保存来源/摘要/时间/AI或人工置信度，不伪装成客观行情值。
9. **闭环**：包含“昨日计划 vs 今日实际”的执行复盘，区分市场、模式、执行、数据问题。
10. **兼容**：新增 `review_score`、新评级、新单票仓位与 `strategy_context` 语义；不得复用旧 `composite_score`、`verdict`、`sentiment.position_pct` 改义。旧 P/A、候选过滤和 sizing 默认不变，先影子输出。

## 4. 技术核心架构（L2 结构增量）

- **入口**：继续 `commands/prep.py`；不新增顶层命令，避免无谓扩大 CLI/E2E 契约。
- **公共入口/用例**：继续 `review_account/prep/main.py` 与 `service.py::run_prep`；采集→读回→纯计算→快照的两段式不变。
- **采集**：扩展 `collectors.py` 注册表和现有 provider；新增原始 asset_type，优先扩展现有 THS/Quote/CNInfo 字段。官方交易所/巨潮优先，其他结构化源次之，DOM 再其次，OCR 最后。
- **计算**：在 `review_account/prep/` 内按职责拆分市场/主线与角色/评分与仓位/playbook；`compute.py` 可保留兼容聚合，不建设新的根级模块。
- **快照**：优先沿用 `prep_assets` / `prep_snapshots` JSON 契约并升级快照版本；Agent 自然语言报告与确定性快照分离。T+1 反馈使用 auction/新时点资产，不修改 T 日原始资产。
- **因子**：新信号按项目约定注册版本化因子用于评估；`infra/factor` 只读产物，禁止 import `review_account/*` 或 provider。不得让 prep 与 factor 形成循环依赖。
- **Skill**：扩展现有 `skills/dragon-quant` 的路由/输出解读，业务权重与参数仍由项目权威持有；Skill 只消费结构化上下文。
- **依赖**：commands → prep 公共入口 → service → collectors/compute → infra 叶子；factor 只读快照，禁止反向 import；不引入 Node 作为 dragon-quant 运行依赖。
- **东财约束**：当前 prep 文档明确“排除东财”。默认主路径不得依赖东财；调研中的东财能力只列可选补充，若推荐启用必须单列为用户决策并同步 owner 文档。
- **历史/时点**：same_day_only、真实 as_of、行日期/分页覆盖校验、缺失≠0、原始响应血缘必须保留。历史不可重建的因子只能从真实采集日开始验证。

### 设计模式与动机

- **Adapter**：多个数据源与测试替身统一为 provider 能力，隔离字段/单位/鉴权差异。
- **Strategy**：不同市场角色使用不同 scorecard/仓位上限，避免一套权重硬套所有股票。
- **Chain of Responsibility**：硬风险否决与数据资格检查按优先级短路，防止高分绕过风险。
- **State Machine**：`pending → confirmed / weakened / invalidated / unknown` 等 T+1 状态及允许动作，避免 Agent 自行编状态。
- **Registry**：沿用 collector/factor 注册表，新增因子不改流水线骨架。
- 不使用 Observer/DI 容器；现有直接调用与装配足够，避免为“完美”过度抽象。

## 6. main 单次验收关注点

- 是否真正满足“每只详细标的量化分 + 单票仓位 + Agent 次日策略”，而非仅扩字段。
- 是否混淆旧五维分、T 日分、T+1 反馈和置信度；是否引入未来函数。
- 是否有完整可执行的基线数字，同时明确未验证并默认影子。
- 是否错误依赖东财、登录态或 OCR 才能走通主路径。
- 是否保持旧交易行为默认不变、依赖方向与因子层硬约束。
- **详细复盘池不得直接扩写旧 `candidates`**：旧数组继续保持近五日真龙范围，新详池用 `review_candidates` 或默认 legacy 的显式作用域隔离，确保默认 auction/buy/review-account 集合逐只不变。
- 是否包含全部要求图表、数据可得性、登录/headless/OCR 清单和验证证据。
