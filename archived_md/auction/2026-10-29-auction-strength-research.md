## 0. 调研问题与判定标准

### 0.1 调研问题

1. 为什么当前 `auction` 永远显示“未验证”，其字段假设是否真实成立？
2. 现有四维评分与四类否决在真实资产上是否存在口径、单位或采样失真？
3. 六篇参考资料中哪些思想可以转换为 09:25 时点可计算、可重放、可解释的因子？
4. 哪些参考思想需要当前资产之外的数据，不能伪装实现？
5. 如何向 CLI、JSON、因子层和 Agent Skill 同时提供“强度 + 证据 + 数据质量”，且不输出买卖结论？

### 0.2 判定标准

- **PIT 正确**：只使用 09:25 及之前已经可知的竞价数据；盘后运行不得把收盘价、全天成交额等未来信息回填到竞价分。
- **可计算**：有明确的原始字段、公式、单位、时间窗口和缺失语义。
- **可比较**：沪深不同采样频率、不同股价和流通规模不能直接比较原始计数。
- **可解释**：综合分能追溯到原始值、子项贡献和关键事件；风险事件与数据不足分开。
- **可重放**：`auction --recompute` 零网络，同一批资产重算结果一致。
- **不宣传胜率**：参考资料中的 80%／90% 成功率没有样本和交易清单，不作为本项目有效性证据。

## 2. 当前实现的关键发现

### F1｜“永远未验证”是硬编码结果，不是偶发故障

`registry.SEMANTICS_VERIFIED=False`，正常评分在 `evaluate()` 末尾统一写 `unverified=True`；`rank_auctions()` 只给 `unverified=False` 的记录排名。因子层又以 `unverified is False` 为公共门槛，所以 8 个 `auction_*` 因子当前结构性零产出。

**结论**：需要以真实证据固化字段语义，并区分“字段语义已验证”与“评分模型尚未经过样本外验证”，不能只翻转常量。

### F2｜`matched` 不是全程单调累计成交量，而是虚拟匹配量

真实 36 条资产中：

- 36／36 在 09:20 前出现 `matched` 下降，共 662 个下降点；
- 09:20–09:25 没有一只出现下降；
- 这与 09:20 前可撤单、之后不可撤单的机制一致。

当前 `MATCHED_CUMULATIVE=True` 的名称和全窗口差分口径不成立。末值可以表示最终虚拟匹配量，但 09:20 前的负增量是撤单／重报价过程，不是“负成交”。

### F3｜最后一根明细不是可靠的正式开盘价

- 36 条资产只有 1 条最后时间为 09:25:00；其余最后时间为 09:24:57–09:24:59。
- 所有样本的 `quote.open_px` 均可用。
- 27／36 的最后明细价与正式 `open_px` 相差超过约 0.01 元；个别差异达到数元。
- 现有 `_score_direction()` 使用最后明细价计算 `open_pct`，在真实样本上出现方向与幅度明显失真。

**结论**：正式开盘涨幅必须优先使用 09:25 后可知的 `quote.open_px`；最后明细价只能作为 `last_indicative_price`，两者差异本身可成为末段滑移证据。

### F4｜供需不平衡公式受采样次数放大，跨股票不可比

当前 `imb = sum(unmatched) / final_matched`，对全窗口时点快照求和：

- 未匹配快照被重复累计；
- 沪市约 3 秒、深市约 9 秒一条，采样数量不同；
- 分子是队列快照之和，分母却是末点匹配量，量纲和时点不一致。

真实样本的 `imb` 中位数约 3.38，最大约 **10374.75**，已不是可解释的不平衡指标。

**结论**：改用末点／短窗的未匹配量相对匹配量、流通量或自身历史分位，不跨全窗口累加快照。

### F5｜竞价换手存在“手／股”单位错误

协议口径 `matched` 为手；`float_market_cap / price` 得到股。当前直接用 `matched / float_shares`，少乘 100。

真实样本当前 `turnover_pct` 中位数约 0.002%、最大约 0.016%，与单位遗漏一致。

**结论**：`auction_turnover_pct = matched_lots * 100 / float_shares * 100%`；协议金额估算同样需要 `price * matched_lots * 100`。

### F6｜缺失数据被写成中性 50，违背“缺失不等于一般”

当前多个分支在缺昨收、样本不足、窗口不足、单维异常时给 50 并继续加权；空明细又被 `is_weak=True`。这会把三种不同状态混在一起：

1. 明确弱；
2. 无法评价；
3. 维度缺失但其余维度可评价。

**结论**：`strength`、维度分和因子行允许 `null`；必要输入缺失时整体 `unknown`，非必要维度缺失时按剩余有效权重计算并降低数据完整度。风险否决与数据质量必须是两个独立轴。

### F7｜当前量价配合没有区分可撤单与不可撤单阶段

`_score_vol_price()` 对全窗口 `Δmatched` 与 `Δprice` 同号计数。09:20 前的 `Δmatched<0` 是撤单过程而非真实成交方向，不能和后续阶段用同一语义解释。

**结论**：核心量价因子只在 09:20–09:25 计算；前段单独作为低信任试盘／撤单上下文。

### F8｜“已匹配此消彼长”是当前实现未充分表达的核心证据

参考资料反复强调：价格不动时，应同时观察未匹配量变化与匹配量增量：

- 未匹配卖单减少 + 匹配量增加 → 买方吸收卖单的估计证据；
- 未匹配买单减少 + 匹配量增加 → 卖方打掉买单的估计证据；
- 价格变化时，未匹配量消失可能只是报价档位隐藏，不能直接当成被成交。

当前只有简单的末段均值放大和符号比较，没有“同价位 + 队列变化 + 匹配增量”的联合事件。

### F9｜历史竞价量比可计算，但当前覆盖不足

参考资料定义竞价量比为“当日竞价总量 ÷ 过去五日平均竞价量”。本地资产可以提供同股票历史末点匹配量，但当前 36 个观测中：

- 14 个至少有 1 个历史观测；
- 11 个只有 1 个历史观测，3 个有 2 个；
- 没有股票具备完整 5 日历史。

**结论**：字段和算法可落地；不足窗口必须显式 `null` 并记录 `history_n`，不能拿 1 日数据冒充 5 日均值。

### F10｜盘后采集的 Quote 只有白名单字段可用于竞价评分

真实资产采集时间覆盖盘中、盘后和夜间。Quote 中的 `price / amount / volume / pct / main_net_amount / turnover_rate` 可能已经是 09:25 之后的数据。

可安全使用的字段应限于：昨收、涨跌停价、流通市值、正式开盘价及代码身份等 09:25 时点已确定或静态的字段。不得因 `quote_json` 里有全天字段就顺手加入竞价模型。

### 资料内部冲突的处理

- **匹配量颜色**：采用“只看匹配量高低，不把颜色当独立买卖信号”；颜色来自未匹配方向，不能重复计数。
- **09:15–09:20 价值**：不作为核心强度分；仅保留撤单、试盘、价格波动等低信任上下文。
- **“主力／散户”**：订单没有账户身份，只能命名为“盘口估计事件”，不得输出“主力已控盘／已出货”的事实断言。
- **高开**：只是价格表态之一，不能覆盖强转弱、卖压和量价背离风险。

## 4. 建议进入阶段 2 的因子目录

以下只确定因子及语义，不在调研阶段冻结权重和阈值。

### 4.1 价格与正式开盘

| 因子 | 初步口径 | 缺失语义 |
|---|---|---|
| `official_open_gap_pct` | `open_px / prev_close - 1` | 无正式开盘价或昨收 → null；不得以最后明细冒充 |
| `last_indicative_gap_pct` | 最后明细价／昨收 - 1 | 无最后有效价 → null |
| `final_indicative_slippage_pct` | 正式开盘价相对最后明细价的差 | 任一缺失 → null |
| `post20_price_return_pct` | 09:20 到末点的价格变化 | 窗口不足 → null |
| `tail_price_return_pct` | 末 30 秒价格变化，样本不足按明确规则扩窗 | 样本不足 → null |
| `post20_price_acceleration` | 前后半窗收益／斜率差 | 两个子窗均有效才计算 |
| `post20_max_drawdown_pct` | 不可撤单阶段从峰值到后续低点的最大回撤 | 窗口不足 → null |
| `price_flat_ratio` / `unique_price_ratio` | 同价采样占比／不同价格数占比，按市场采样数归一 | 只作盘口形态，不推断“主力控盘” |

### 4.2 匹配量与流动性

| 因子 | 初步口径 | 缺失语义 |
|---|---|---|
| `last_matched_lots` | 末点虚拟匹配量（手） | 无有效末点 → null |
| `auction_amount_estimated` | `official_open_px * last_matched_lots * 100` | 正式价或匹配量缺失 → null |
| `auction_turnover_pct` | `last_matched_lots * 100 / float_shares` | 流通市值或价格无效 → null |
| `post20_matched_delta_lots` | 末点匹配量 − 09:20 匹配量 | 只读不可撤单窗口 |
| `tail_matched_delta_lots` | 末段匹配增量 | 不与原始采样条数混淆 |
| `tail_matched_acceleration` | 末段单位时间增量相对前段的比值 | 前段基准 ≤0 → null |
| `auction_volume_ratio_5d` | 当日匹配量／同股此前最多 5 个有效交易日的均值 | 必须明确 `history_n`；不足既定窗口 → null |
| `event_density_ratio` | 实际采样数／市场期望采样数 | 只作数据完整度或冷门诊断，不直接等同强度 |

### 4.3 未匹配方向与转换

| 因子 | 初步口径 | 缺失语义 |
|---|---|---|
| `final_unmatched_lots_signed` | 正=买方剩余，负=卖方剩余 | 原始缺失 → null |
| `final_unmatched_matched_ratio` | 带符号未匹配量／末点匹配量 | 匹配量为 0 时单独标记，不除零 |
| `post20_unmatched_change` | 末点与 09:20 的带符号差 | 只看快照变化，不跨全程求和 |
| `tail_unmatched_change` | 末段带符号变化 | 与匹配增量联合解释 |
| `weak_to_strong` | 卖方向转买方向，且满足最小样本／幅度规则 | 未发生与无法判断分开 |
| `strong_to_weak` | 买方向转卖方向，且满足最小样本／幅度规则 | 风险事件，不等同数据缺失 |
| `sell_pressure_acceleration` | 卖方向未匹配绝对值扩大且匹配量同步增加 | 只作风险证据，不给“主力出货”身份结论 |

### 4.4 同价位匹配转换事件

对相邻或短窗记录，先筛选价格未明显变化的区间，再联合计算：

- `sell_absorption_estimate`：未匹配卖量绝对值下降 + 匹配量上升；
- `buy_queue_hit_estimate`：未匹配买量下降 + 匹配量上升；
- `queue_hidden_or_repriced`：价格变化导致原价位队列不可直接比较，只记上下文；
- `early_cancel_estimate`：仅 09:20 前队列下降且匹配量没有对应增加，低信任标记。

这些是**盘口估计事件**，不是订单级成交流水。需要保存事件起止时间、价格、队列变化、匹配增量和计算版本，供 CLI／Skill 引用。

### 4.5 量价协同与背离

- `volume_price_confirmation`：不可撤单阶段价格与匹配量是否同向增强，结合价格收益和匹配增量，而非全窗口简单同号计数。
- `volume_price_divergence`：匹配量加速但价格停滞／回撤，作为风险证据。
- `tail_absorption_strength`：末段匹配增量与方向转换、同价位吸收事件联合，不重复把同一信号在多个维度满分叠加。

## 5. 本期明确暂缓的内容

1. **全市场竞价广度**：需要全市场 09:25 行情，不能用候选池代替。
2. **订单级撤单、账户身份和真实主力行为**：当前只有虚拟撮合快照，不能证明。
3. **09:30 后支撑压力与盘中大单确认**：需要开盘后分时数据；只能由 Skill 标为后续观察点，不得回填进 09:25 分。
4. **完整 5 日量比的历史覆盖**：等待资产逐日积累；缺少历史就是缺失。
5. **胜率提升断言**：当前样本仅 5 日、22 只且候选选择有偏，不能作为样本外回测。
6. **ML 排序器**：没有足量标签和独立样本，冷启动不可解释且易过拟合。

## 6. 候选技术方向比较

| 方向 | 内容 | 评价 |
|---|---|---|
| A. 最小修补 | 翻转 `SEMANTICS_VERIFIED`，修开盘价与×100，保留旧四维 | 工作量小，但供需采样失真、缺失中性分、事件证据不足仍在，达不到可审计目标 |
| **B. 证据化重建（推荐）** | 先修字段语义，再以 09:20–09:25 为核心重建价格／匹配量／未匹配／转换／量价因子；独立数据质量与风险事件；新增版本化 Skill 上下文 | 能覆盖本次“强度 + 证据 + 报告”的目标，仍可确定性重放与逐项测试 |
| C. 学习式排序 | 用 LambdaRank／小模型学习竞价到收益 | 当前无足够标签，违反可解释与样本外要求，拒绝 |

阶段 2 建议采用 B，并保留一个“旧字段兼容层”，避免 JSON／因子消费方因新增结构直接崩坏；不在本期设计或修改 `buy`。

## 7. 对阶段 2 的硬输入

1. 正式开盘价与最后指示价分离；任何方向评分不得继续默认使用最后明细价代替正式开盘。
2. `matched` 统一命名为虚拟匹配量（手），核心差分只在不可撤单窗口；金额与换手显式×100。
3. 不再对全窗口未匹配快照求和；沪深采样频率必须归一。
4. 强度、风险事件、数据质量、模型验证状态四轴分离；缺数据不得写 0／50，也不得当成明确弱。
5. 新版本化 `strategy_context` 至少包含：候选血缘、逐只原始因子、子项贡献、关键事件、窗口、数据质量、缺失原因和允许的盘中观察动作。
6. CLI 保持简短，只展示强度与最关键证据，不输出买卖建议；详细解释交给 JSON + Skill。
7. 因子层新增信号默认 `default_enabled=False`，缺失=无行；不得把同一事件在综合分和多个新因子中重复当作独立证据。
8. 为真实资产建立离线语义回归样本：至少覆盖沪深、正负未匹配、末点非 09:25、09:20 前匹配量下降、历史不足和正式开盘缺失。
9. 文档中的权重与阈值全部标为待验证基线；不得以 36 条资产宣称胜率提高。
10. 所有新增计算保持纯函数；采集与 `--recompute` 共用同一评分入口。
11. 阶段 2 必须列出旧 `strength / is_weak / unverified / rank` 的全部消费方。修改这些字段可能在不改 `buy` 代码的情况下改变其行为；兼容层必须明确哪些旧字段保留、哪些新字段隔离，不能把“不改 buy 代码”误写成“buy 行为绝对不变”。

---

## 8. 已知限制

- 真实样本只用于验证字段口径和暴露实现失真，不用于证明因子有效。
- `open_px` 是 09:25 正式开盘价，09:25 整点运行时需要允许行情稍微延迟；若缺失应降级，不得强造。
- 末点虚拟匹配量不必然等于交易所发布的正式竞价成交量；`auction_amount_estimated` 与换手均须保留 `last_time` 和估算语义，后续有官方成交快照时再单独校准。
- 同价位匹配转换仍只是快照推断，新挂单也可能改变未匹配量，输出必须带 `estimate` 语义。
- 竞价量比的历史不足会在早期造成稀疏因子，这是预期行为，不应通过填充提高覆盖率。
