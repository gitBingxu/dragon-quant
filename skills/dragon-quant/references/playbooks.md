# playbooks — 异常分流手册

**何时读我**：命令报错、结果降级、出现空池、版本不一致或同步失败时。每节固定格式：症状 / 诊断 / 处理 / 停止条件 / 禁止动作。

## 1. CLI 缺失或版本漂移

- **症状**：`dragon-quant: command not found`；或 PATH 上的版本低于 skill 要求；同一结果与文档不一致。
- **诊断**：`dragon-quant -v`；项目内用 `.venv/bin/python -m dragon_quant -v`；`npx dragon-quant-skills doctor` 同时显示 skill 版本、要求的最低 CLI 版本、探测到的 CLI 与路径。
- **处理**：在项目虚拟环境安装/升级 dragon-quant；确认调用的是 `.venv/bin/python`，不要混用 PATH 上的旧版本。
- **停止条件**：版本仍低于 `min-cli-version` 时停止执行新命令。
- **禁止动作**：不要自动 `pip install`；不要用系统 Python 污染环境；不要把版本漂移说成“数据问题”。

## 2. 雪球 Cookie 缺失或失效

- **症状**：个股 K 线/分时请求返回空或 403；回退链路失效。
- **诊断**：`dragon-quant data cookie-status`；确认当前路径是否真的依赖雪球（TDX 首选时可能不需要）。
- **处理**：需要时由用户确认后执行 `dragon-quant data cookie-set` 或 `dragon-quant data cookie-fetch`（T2，写凭据）。
- **停止条件**：Cookie 仍无效时，不要声称扫描/回测结果完整；说明降级。
- **禁止动作**：不要回显 Cookie/token；不要把凭据写进日志或仓库；不要在只走 TDX 的场景强行要求 Cookie。

## 3. THS 403 / 频控

- **症状**：同花顺板块或成分股请求被 403，重试后仍失败。
- **诊断**：看输出中的 `degraded`/`sources` 是否标到 THS；确认是否短时间高频调用。
- **处理**：等待退避后再试；优先走 TDX 链路；单维度失败时按降级继续，不要中断整个扫描。
- **停止条件**：连续 403 且 TDX 也不可用时停止，向用户说明数据不完整。
- **禁止动作**：不要密集重试或并发轰炸；不要伪造板块数据。

## 4. TDX 失败与数据源回退

- **症状**：TDX 请求失败，结果仍返回但标记降级。
- **诊断**：看 `sources`、`degraded`、`api_stats`、`provider` 相关输出。
- **处理**：接受 THS/雪球/腾讯回退；在解读中明确哪一维降级、影响了什么。
- **停止条件**：关键维度全部不可用时停止，不要用空数据补位。
- **禁止动作**：不要把回退结果说成“TDX 正常”；不要隐藏 `degraded`。

## 5. 非交易日与时段门禁

- **症状**：`prep` 报“请 16:40 后运行”；`buy`/`sell` 报“尚未开盘”或“非交易日”；`auction` 在 09:25 前没有数据。
- **诊断**：确认当前日期/时间与目标交易日；`prep` 当日需 ≥16:40，`auction` 当日需 ≥09:25，`buy`/`sell` 实时需交易时段。
- **处理**：等待门禁；历史复盘改用 `--date`（`buy`/`sell` 还要 `--at`）；非交易日不要假装有当日数据。
- **停止条件**：门禁未满足时停止，不执行写操作。
- **禁止动作**：不要用 `--force` 绕过交易日或 09:30 前限制；不要伪造“今天”的行情。

## 6. 停牌与日K兜底

- **症状**：`data_quality=daily_fallback`；`fallback_days` 非空；`suspended_codes` 出现；某些标的没有买卖评估。
- **诊断**：看数据质量三态、停牌列表、不可用列表；确认是分时缺失还是当日日K缺失。
- **处理**：说明兜底成交价是保守近似；停牌持仓冻结、按最近可得收盘价估值；分时相关规则在兜底日自然跳过。
- **停止条件**：日K完全无历史或预热不足时停止，不持久化部分结果。
- **禁止动作**：不要把兜底近似说成真实成交；不要把停牌说成“没有信号”。

## 7. 空池、快照缺失与回退

- **症状**：`auction` 空池；`prep` 候选为空；`buy`/`review-account` 候选池回退；输出出现 `fallback_reason`。
- **诊断**：看 `pool_source`、`fallback_reason`、`prep_snapshot_date`、`dragon_source.window_days`；确认 T-1 快照是否存在、候选是否全部被忽略。
- **处理**：解释回退原因；推荐集为空时可能回退到最近若干交易日的龙头并集；历史缺口不要假装能补采。
- **停止条件**：候选池与回退池都为空时停止，明确说“无参与标的”，不要编造信号。
- **禁止动作**：不要把空池说成“市场弱”；不要把回退池说成“今天的盘前推荐”。

## 8. 因子缺失或默认关闭

- **症状**：`factor query` 无数据；`factor build` 报告 `missing_source`；`eval` 返回 `insufficient_data`。
- **诊断**：`factor list` 看是否默认关闭；确认源表（扫描/量价/复盘/竞价/财务）是否可用；确认日期与版本。
- **处理**：显式 `--only` 构建默认关因子；源不可用时如实说明；`insufficient_data` 是有效结论，不是命令失败。
- **停止条件**：源整体不可用且没有历史行时停止，不要用 0 或中性分填充。
- **禁止动作**：不要把“缺失”说成“0 分”；不要为了凑样本改口径。

## 9. 资产同步失败

- **症状**：`assets push/pull/verify` 非零退出；出现失败分区、冲突、收缩被拒、锁占用。
- **诊断**：看 `failed[].kind`（source/transport/manifest/shard/shrink）、退出码（1 部分失败、2 配置/网络/参数）；确认没有并发进程持有同步锁。
- **处理**：修复后重跑；失败分区可按已成功水位续传；恢复优先 `--target-dir` 隔离目录。
- **停止条件**：配置/凭据/网络不可用时停止；不要反复重试放大问题。
- **禁止动作**：不要在未确认时用 `--allow-shrink`；不要在主线库执行 `assets pull --force`；不要回显凭据。

## 10. 回放写库与幂等

- **症状**：历史回放提示“未落库”；同一信号重复运行；卖出结果与上次不同。
- **诊断**：看输出中的幂等提示；确认信号是否已平仓或状态已变化；确认回放时点 `--at` 一致。
- **处理**：说明回放会写库；幂等命中时结果可能标注未落库；需要可复现时固定 `--date` 与 `--at`。
- **停止条件**：状态不一致且无法解释时停止，先只读核对再重跑。
- **禁止动作**：不要手工改业务表来“修正”结果；不要并发运行多个写库命令。

## 11. 策略上下文缺失或版本不认识

- **症状**：`prep --json` 没有 `strategy_context`；`context_version` 不是 `sc_v1`；`positions[]` 为空但 `review_candidates` 有内容；`feedback_plans[]` 全为 `expectations_unavailable`。
- **诊断**：确认快照 `version` 与 CLI 版本是否匹配；确认是否用 `--date` 读到旧快照；确认 `data_quality.missing` 是否覆盖全部标的；确认是否在非盘后时段读数。
- **处理**：版本不匹配时先说明，再由用户确认后用 `--recompute` 重算（T1，写快照）；旧快照只输出旧摘要（四行 + 逐只清单），并明确「没有结构化策略上下文，无法给出条件化明日策略」。
- **停止条件**：`strategy_context` 缺失且无法重算时停止，不拼凑阈值、仓位或买卖动作。
- **禁止动作**：不要把旧 `sentiment.position_pct`（市场参考仓位）当单票建议仓位；不要在缺上下文时假装有正负反馈条件；不要编造 `feedback_plans`、`expected` 或 `allowed_actions`。
