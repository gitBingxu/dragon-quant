# 账户策略与统一执行协议

`review-account` 和 `buy/sell` 通过同一 `TradingEngine.step` 执行。策略只在 `strategy.py`，成交与仓位只在 `execution.py`；历史和实时层只提供事件、读写结果。

## 数据与候选

- 交易时区为 Asia/Shanghai，使用上证指数 SH000001 日K确认交易日。历史回测只纳入已收盘交易日，并加载区间前的候选日期和至少20个交易日日K预热。
- 前3个真实交易日各读前5只龙头，按代码合并，保留最优排名（同排名取高分），再取前5。某日空池不向更早日期补票，持仓和不合格候选也不由第6名补位。
- `is_true_dragon=False` 或综合分低于50不买；旧记录的空标记维持可用语义，不重写旧数据。
- 日K与5分钟K均使用不复权价格，量额按雪球口径；开盘量能和指标只来自上一个交易日日K，不使用候选入池日的旧量额，也不回退到当日最终量额。
- 每个交易日优先要求48根真实5分钟OHLC（上午09:35–11:30、下午13:05–15:00）走盘中撮合；实时只检查已结束部分。重复、缺点、跨午休、无效OHLC均拒绝，不把报价曲线伪装成5分钟K。
- **日K兜底**：若当日任一相关个股缺完整5分钟K（雪球分时约仅保留14天，多月回测常见），整日降级为日K兜底——开盘买点按开盘价成交，收盘按当日OHLC判定止损/止盈；`intraday_bars` 恒空，分歧买龙、高开未封板窗口、同根K保本排序等分时规则自然跳过。买卖决策仍复用同一 `evaluate_buy/evaluate_sell`。兜底日成交价为保守近似（止损跳空按开盘价否则按止损线，保本按完整成本线，其余按收盘价），结果 `data_quality` 标为 `daily_fallback`/`mixed`/`strict_5min`，并附 `fallback_days`。
- 日K本身缺失（当日或20日预热不足、无效OHLC）仍严格报错，不保存部分回测；停牌、除权口径缺口需先解决。

## 事件与成交

1. 开盘事件判断开盘买点；之后每根已完成5分钟K判断盘中规则；14:55判断尾盘规则。
2. 先撮合以前产生的待执行信号，再判断新的信号。同一事件卖出优先于买入。
3. 历史信号在下一可交易事件使用下一根K开盘价并加滑点；实时等待决策之后的新鲜报价。不得在看到一根K结果后以该根已过去的价格成交。
4. 买入信号等待超过5分钟失效；当日卖出后不再买入，跨日取消未成交买入信号。未成交卖出信号保留，直至出现可成交报价。
5. 涨停附近不可假定买得到、跌停附近不可假定卖得出；加滑点后超涨跌停价的委托不成交。跳空按可执行价处理，不能补填成本线或止损价。
6. T+1禁止当日卖出，但跟踪买入后的已观察峰值；不把买入前高点算成盈利。当前K高点只能影响后续事件，不能倒推同K内先涨后跌。
7. 15:00更新估值和峰值，不凭最终收盘价产生并回填成交；实时可在15:00–15:05额外调用同步收盘状态。

成交假设仍是纸上撮合，不模拟交易所排队和全部市场冲击，真实执行不保证达到回测成交价。

## 买入

同一决策时点按信号优先级、排名、综合分、代码择优。默认每天最多买一次，最多5个同时持仓。

| 买点 | 时点 | 条件 |
|---|---|---|
| MA5承接（300） | 开盘 | 上日成交额≥2亿、换手≥5%；开盘相对上日MA5不超过+3%，缺口在(-3%,7%]，未封死涨跌停 |
| 突破前高（200） | 开盘 | 上述量能基础；开盘高于上日最高、缺口[0,5.5%]、距MA5≤12%、上日换手8%–35%、成交额≥5亿 |
| 分歧买龙（400） | 默认10:00 | 上日前连续至少2个缩量一字涨停；开盘低于涨停价×0.998；完整前6根5分钟K最低不破昨收、末根收盘≥首根开盘 |

分歧买点不套用量额/换手门槛，但不再把某根K瞬间触及涨停直接当成承接成立和可成交。开盘买点先发生，不等未来分歧信号反向择优。

## 卖出

每个有效事件依次检查，命中后产生待执行信号，不保证止损价或保本价成交。

1. 首个可卖日触及-3.5%紧止损，此后触及-5%硬止损。
2. 之前已观察峰值浮盈≥8%后，当前完成K收盘自峰值回撤≥3.5%，或14:55跌破MA5，移动止盈。
3. 之前峰值浮盈≥6%后触及完整成本保护线；保护线含买入成本、卖出滑点、最低佣金及印花税。跳空或延迟仍可能亏损。
4. 高开≥7%，第一根5分钟K未触涨停则清仓；高开[5%,7%)，前6根未触涨停则清仓。
5. 14:55收盘弱势或低于当时MA5清仓；弱势容忍带为1%，小幅低于开盘但未破MA5/昨收时不触发弱势卖出。
6. 首个可卖日14:55仍封板且未减仓过则卖半仓（整手，不足半手则全卖）；弱势清仓优先。
7. 14:55累计成交量比上日全天增加≥30%且未封板则清仓。

不因最长持有天数或固定盈利百分比强制离场。`take_profit_pct`、`max_hold_days` 保留为历史配置字段，不在当前决策路径使用。

## 费用与实验参数

基础默认：初始资金10万元、买卖滑点各0.2%、佣金0.03%、最低佣金每笔5元、卖出印花税0.05%、100股整手。默认保持原全可用现金仓位基线。

可通过共同的 `--config params.json` 或 API `strategy_params` 指定：

```json
{
  "max_position_pct": 25,
  "risk_per_trade_pct": 1,
  "ma5_min_distance_pct": -1,
  "require_rising_ma5": true,
  "trailing_atr_multiple": 2,
  "next_day_half_enabled": false
}
```

这些是实验参数，不是已经证明更赚钱的默认值。风险预算按紧止损、滑点与费用估算；跳空可能使实际损失超过预算。ATR回撤阈值取固定回撤与ATR倍数的较大者。

## 命令与持久化

```bash
python -m dragon_quant review-account --from 20260907 --to 20260911 --config params.json
python -m dragon_quant buy --account experiment --config params.json
python -m dragon_quant sell --account experiment
python -m dragon_quant account --account experiment
python -m dragon_quant buy --date 20260907 --at 10:00 --account replay
```

实时命令不允许指定 `--at`，历史日期必须指定 `--at` 且不能混用当前报价。命令为单次执行，需主动在09:30、各5分钟边界、14:55调用，产生信号后再次调用取得更新报价；错过开盘不补做开盘买点，`buy` 同时处理卖出以保证先卖后买，`sell` 禁止新增买入。

新账户保存完整参数，已有账户读取保存参数，不允许静默换策略；不同参数请用新的账户名。持久化 `live_engine_state` 与现金/持仓/交割单同事务提交，revision拒绝并发旧状态，事件时间戳防止重复执行。旧账户从原表导入，不清空历史。回测每日快照的 `positions_json` 保存完整未平仓状态，已平仓表保留原语义。

## 验证与限制

`evaluation.compare_strategies` 比较基线、风险预算、入场质量、ATR/半仓实验；按时间60%训练、20%验证、20%独立测试。各段以独立账户开始，未平仓按期末估值，不把未来退出用于前段评价。训练/验证至少各10笔已平仓交易且回撤不超过15%后才选择参数，再打开独立测试并做双倍滑点压力测试。不自动改默认参数。

2026-09-13真实数据审计：6月个股5分钟数据不可得；近期部分候选缺分钟。因此多月回测目前几乎全程走**日K兜底**（如 2026-06-26~09-07：51 个交易日中 45 天兜底、6 天严格盘中，`data_quality=mixed`）。兜底日成交为保守近似，与严格盘中撮合不是同一精度，比较策略时须结合 `data_quality`/`fallback_days` 一并判断，不能把兜底结果当作分时级精确收益。`evaluation.compare_strategies` 覆盖不足时返回 `insufficient_data`，不据此宣称新策略提高收益。现有评分历史也可能来自不同版本，不能重算后冒充当时已知信号。
