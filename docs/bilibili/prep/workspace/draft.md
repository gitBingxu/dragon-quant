## Executive Summary

五份材料的最强共识不是某个神奇指标，而是决策顺序：**先判断市场与情绪，再识别主线及其核心角色，随后选择个股并匹配仓位，最后为次日不同反馈预先写好动作，并用实际执行结果反向校正。**[1][2][3][4][5]

当前 prep 已有可复用的“采集资产 → 健康过滤 → 纯计算 → 可重放快照”骨架，但语义仍是“近五日真龙池 + 市场总仓位 + 个股四档定性评级”。候选的 `composite_score` 是入选日五维分，不是 T 日复盘分；CLI 的仓位是市场情绪仓位，不是单票建议仓位。[6][7][8][9]

本研究建议将目标产品定义为四层产物：**市场状态、主线/角色图谱、个股量化评分与独立建议仓位、T+1 条件化策略上下文**。量化层负责可复现事实、分数、否决和阈值；Agent 只基于这些结构化事实生成自然语言策略，不能补造行情或改写硬否决。盘后评分与次日触发必须分开，否则会把未来函数带入复盘。[7][10][15][16]

数据上应优先使用系统已经采集但未消费的字段，再扩展免费结构化接口；headless DOM 用于补充页面独有字段，截图/OCR 只作低置信度补充。封单、竞价等时点数据必须当日落盘，不能用后来的实时快照伪造历史。[16][24][29][35][36]

## 一、五份文档分别讲了什么

### 1. 万战寻道：回顾—前瞻，两条复盘路径

**流程**。先坚持客观，再梳理当天行情、核心表现和变化原因；前瞻时依次回答“正常预期是什么、超预期是什么、如何识别、做谁、怎么做”。理解力型路径是指数 → 情绪 → 题材 → 核心 → 节奏/仓位；模式型路径允许先从图形筛股，再叠加题材、股性、风格、情绪和仓位。最后复盘最优解、亏损、卖飞与大回撤。[1]

**维度与因子**。指数看流动性区间与变化、支撑压力、进攻/防守载体、主动/被动和外部扰动；情绪看主板/创业板生态、N 字/突破/二波等形态偏好、低价/市值/趋势或接力风格、高度序列、高低位共振、修复/分歧；交易复盘看胜率、赔率和回撤归因。1 万亿与 5000–7000 亿、25/30 亿市值、5% 大回撤等均是特定案例或经验，不应直接固化。[1]

**次日反馈**。被动上涨的正常预期是分歧；指数弱时板块抗跌或主动分离是超预期。逆大趋势中的修复只能按低仓位套利，方向不明时控仓或不做。龙头高度、空头龙与抱团瓦解同时充当情绪和风险锚。[1]

### 2. 短线狂徒张三：大盘—板块—个股与明确仓位经验

**流程**。先用指数量价、涨跌家数、涨跌停和炸板率判断水温，再从板块涨幅/涨停分布中锁定前三及先锋、中军、龙头，最后检查个股是否主流、消息、买卖点和交易日志，制定仓位—选股—买点—预期处理计划。[2]

**维度与因子**。市场层是量、指数、广度、涨跌停、炸板率；板块层是前三、进攻/防御和资金逻辑；角色层包括率先非一字涨停的先锋、通常 200 亿以上且涨停的中军、流动性/带动性/涨幅突出的龙头；执行层关注 5/10 亿成交额、胜率与盈亏比。炸板率 20%、好环境 60%–80%/差环境 20%–30% 仓位是原文明确规则，但没有样本和回测支撑。[2]

**次日反馈**。放量上涨偏正、无量上涨防虚高、放量下跌防延续；炸板率高或防御板块领涨时降仓。预期一致可持有，不一致则处理，但原文没有给精确止损公式。[2]

### 3. 无名游资：主线前三与看涨量价的双条件

**流程**。先用特定工具确认题材排名前三，再从对应 ETF 主要持仓中筛选股票，最后要求技术/量价看涨；两个条件缺一不可，任何一项破坏即退出。[3]

**维度与因子**。题材价值看主线排名与利好，载体看 ETF 持仓，个股看大阳线、缩量、前高、放量大阴线和估算成本，纪律看场内外共识。主线至少上涨 15%、案例 10% 仓位是经验/个案；“主力成本、建仓、出货”由 K 线主观推断，不能当成真实资金字段。[3]

**次日反馈**。继续保持主线前三且技术看涨才持有或参与；跌出前三或放巨量下跌即退出，到前高可减仓。该“前三”是特定工具口径，与其他文档的板块涨幅/涨停数前三不能混用。[3]

### 4. 华东导弹：全量涨停、逻辑持续性与前置节点

**流程**。每天至少完整过一遍涨停并逐股查逻辑，研究其故事、发展和后续催化；了解市场主流预期但保持反向质疑，从多条已选出的主线中比较可持续性，把买点前置到冰点转强或回调后再确认，而不是等一致公认或 4 板后才发现。[4]

**维度与因子**。信息面看涨停原因、后续消息、社会传播与官媒催化；情绪面看低谷、转强、回调确认、高潮和一致；执行面看自己的开仓反馈、封板率和成功交易回溯。作者明确否认单一量、盘口或指标能判断真假弱转强与穿越，因此不能把本文误读成技术评分公式。[4]

**次日反馈**。高潮后接力即使封住也可能次日走弱，低谷节点的炸板反而更容易修复；不要每天猜顶或机械套用固定周期，只有真实反馈和逻辑变化才改变动作。[4]

### 5. 江浙陈某：每日六步 + 阶段性第七步

**流程**。每日依次看大盘与赚钱效应、热门板块、昨日/今日热门股及题材切换、自己的交易、股票池更新、次日计划；每周/月/季再总结个人胜率、市场风格和指数阶段。[5]

**维度与因子**。市场看指数、涨跌幅分布、非一字涨跌停、高换手前 40 上涨占比、昨日涨停表现、跌停高低位结构；板块看涨停分布、消息、异动数量/强度/时间；股票池看新老龙头、今日最强、整体高标及同题材高板；计划看高开/回踩、买卖数量和环境。7%–8% 上攻、14:30 异动是案例观察，不是固定阈值。[5]

**次日反馈**。昨日核心共同上行是正反馈，分化或新热点数量/强度更大说明旧线弱化；同题材高板倒下是关联风险。概念仍契合且形态未坏可持有，赚钱效应恶化先减仓，概念恶化退出。[5]

## 二、跨文档综合：理想复盘闭环

以下是本研究的综合，不冒充任何单篇原文公式：

1. **市场背景**：指数量价、全市场成交额、外围与消息，回答“能不能承担风险”。
2. **情绪与生态**：广度、涨跌停、炸板、昨日涨停溢价/晋级、连板高度、活跃股与高低位结构，回答“赚钱效应在哪里、在增强还是衰减”。
3. **全量涨停与主线**：不只按涨幅排名，还看涨停集中度、板块主动性、梯队、持续天数、新旧线切换和消息逻辑，回答“资金主战场是什么”。
4. **角色与锚**：区分最高标、板块龙头、先锋、中军、容量核心、跟风/补涨与空头锚，回答“谁代表市场、谁影响谁”。
5. **个股与仓位**：个股质量、主线地位、封板、资金、筹码、股性和风险共同形成分数；仓位与分数、角色、市场状态及数据完整度匹配。
6. **次日多情景计划**：为正常、超预期、低于预期分别定义可观察条件和动作，而不是收盘后直接给无条件买入。
7. **执行复盘**：比较计划与实际，区分市场判断、模式、执行和心态问题，沉淀胜率、盈亏比及因子有效性。[1][2][4][5]

### 不能强行统一的分歧

- “主线前三”可以是某一种交易纪律，但另一篇允许多条主线并行轮动，不能变成全产品唯一真理。[1][3][4]
- 技术量价适合验证与择时，逻辑持续性用于解释能否穿越；把两者组合是产品选择，不是五篇共同证明的公式。[3][4]
- 科技领涨不能自动等同主动进攻，需要排除指数被动带动与单日消息刺激。[1][2]
- 情绪周期可以输出概率状态和证据，不应宣称“退潮后必修复”等确定性阶段机。[1][4]

## 四、对产品方向的研究性建议

1. **全量观察、分层输出**：全市场与全部涨停用于市场/主线计算；详细评分覆盖近期真龙、T 日主线核心、情绪锚和持仓关联标的；建仓建议只给通过资格闸门的少数标的。
2. **三类分不能混**：市场情绪分、主线持续分、个股复盘分分别回答不同问题；数据置信度另列，不藏进分数。
3. **单票仓位独立于组合**：输出占总资产百分比，不做多标的加总约束；同时保留市场状态系数、角色上限、风险否决和数据不足上限。
4. **角色化而非一把尺**：龙头、中军、先锋、补涨对成交额、市值、封板和高度的要求不同；正负反馈也必须相对各自预期，而非“高开一律好”。
5. **盘后预判与次日验证分离**：T 日只保存预期基准和预备仓位，T+1 竞价/盘中只追加新时点结果，不回写 T 日分数。[15][16]
6. **量化事实与主观理解并存**：消息逻辑、社会传播和故事持续性保存来源、摘要、时效与人工/AI 置信度，不伪装成客观行情分。
7. **兼容下游**：新增字段而非静默改变旧 composite_score、verdict、position_pct；现有 P/A 排序、候选过滤和 sizing 只有显式开关才能迁移。[10]

### 2. 数据获取优先级

1. **已采未用**：先扩展 prep 对 THS `order_volume`、首末封、Quote 封单/流通市值/量比等字段的持久化与计算。[12][13]
2. **已有免费结构化补充**：按需要引入 lbtt、fuyao、东财、数猫等适配器，但保留来源、ST 口径、单位和历史深度；当前 prep 文档有“排除东财”约束，若最终选用东财必须由用户显式变更该约束，不能静默接入。[6][17][18][19][24]
3. **本地派生**：情绪、主线、角色、晋级、筹码和计划执行都由统一版本化算法计算，不假装是上游原生事实。[19][20][25]
4. **headless / OCR**：只有页面独有关键字段且无结构化出口时才使用；先 DOM，后截图/OCR。问财 DDE 已证实需要登录 cookie + hexin-v，浏览器自动化的合理用途是刷新令牌，而不是规避登录。[23]
5. **不可可靠获得**：完整历史委托队列、真实逐笔撤单意图、历史板块成员、未按时采集的竞价/封单时序，以及“主力真实成本”应标为未知或需付费/专门数据，不用近似值冒充。[16][21][24][25]

### 3. 外部匿名实测的补充与纠偏

- 东财公开涨停池页面和 JSON 本次无需登录，字段与代码证据一致；但 2026-01-05、2025-10-27、2024-10-25 等旧日期样本返回空池，且 `qdate` 仍显示最近交易日。因此 HTTP 200、`rc=0` 或 `qdate` 都不能证明历史补采成功，必须校验实际行日期/覆盖。[28][29]
- 东财直接给“封板资金”，不直接给原始封单量。只有在保存涨停价、金额单位和股/手换算后，才能以 `fund / 涨停价` 生成**估计封单量**；封成比也要明确金额或量口径。Tushare THS 文档虽有直接封单量/额及 2023-11-01 以来历史，但要求 8000 积分，且单位文字有歧义。[29][31]
- 同花顺匿名精简 `dataapi` 请求本次只返回精简字段；当前 dragon-quant 使用完整 field 参数集并声明有 `order_volume` 等字段，两者请求不同，不能据此判定现有完整接口失效。在线字段覆盖和单位仍应实测校准。问财复合查询则出现了登录框，不能视为免登录源。[12][30][31]
- 同花顺公开复盘文章的市场摘要可走 DOM，但逐股内容嵌在长图中，需要进入动态热点页或 OCR；这类文本适合作题材逻辑证据，不应反向伪造精确盘口字段。[32]
- 深交所官方可直接返回龙虎榜汇总和买五/卖五席位 JSON，上交所也有公开动态表；交易所历史 L1/L2 与完整盘口则属于付费产品，免费当前快照不能替代。[33][34][35][36]
- 东财方法页明确“主力资金”是供应商基于委托/成交自行计算，不是交易所标识的真实机构账户流。筹码同理是模型估计，不是登记结算逐账户持仓。[37][39]
- 巨潮公告可匿名查询元数据并下载 PDF，风险事件和财务语义需要本地文本抽取，图片型文档才走 OCR。解禁、停复牌和监管查询可自动补充，但动态表格/正文仍需 DOM 与发布时间血缘。[38][40]
- 官方宏观/指数页面存在动态 DOM 与 WAF 边界；国家数据内部请求本次 403，中国货币网和中证指数静态抓取也未得到完整动态表格。当前已有的 TDX/Yahoo 日 K 主路径应保留，官方页面用于补充而不是未经验证地替换。[41]

### 4. 明确需要登录态、headless 或 OCR 的项目

| 项目 | 建议方式 | 需要用户配合/注意事项 |
|---|---|---|
| 问财 DDE、复合涨停字段查询 | 登录后的结构化请求；headless 刷新 `hexin-v` | 需要用户提供合法登录 Cookie；不得把凭据写入仓库、快照或日志。[23][30] |
| 同花顺公开复盘长图 | 优先打开动态热点复盘 DOM；无文本层时截图 + OCR | OCR 结果只作低置信度文本证据，需原文链接、截图哈希和抽样复核。[32] |
| 交易所/官方动态宏观与指数表 | headless DOM 或官方下载文件 | 优先结构化下载；WAF/403 时降级，不绕过访问控制。[34][40][41] |
| 图片型公告 PDF | 先 PDF 文本抽取，失败后 OCR | 保存公告时间、URL 与文本提取方式，避免把 OCR 错字用于硬风险否决。[38] |
| “九言公社”题材排名及 ETF 前五持仓 | 暂列未证实；可用现有板块成员/行情替代 | 转写名称不足以定位可靠接口；若要忠实复现，需要用户提供真实产品 URL，之后再判断是否 DOM/登录。[3] |

### 5. 结论

目标产品所需的大部分客观因子可以自动化，但应分成三种可信度：**交易所/公告原文、供应商行情与算法值、本地派生/AI 文本证据**。真正的硬边界不是“会不会爬”，而是历史时点是否曾被保存，以及数据语义是否足以支撑交易决策。[18][24][29][35][36][37][39]

## 六、限制与权衡

- 五份方法论文档均为 Whisper 转写稿，存在误字、口语省略和案例语境；没有可复验样本、成本或阈值敏感性，不能据此声称任何规则有效。[1][2][3][4][5]
- 本研究把“理想产品”与“当前能自动获取”分开。因子可获取不代表有预测力，所有权重、阈值和仓位映射仍需样本外、交易成本与可成交性验证。
- 免费资金流、筹码和“主力成本”多是供应商估算或图形代理，不能解释为真实账户行为；龙虎榜也只覆盖上榜样本。[22][33][37][39]
- 封单、竞价和网页盘口有时点性，历史缺口无法靠今天数据补齐；截图/OCR 的误识别风险高于结构化接口，不应单独触发硬买入或硬否决。
- 新评分和 Agent 文本若未经验证直接接入 buy/sell，会同时改变产品解释与真实交易行为，因此必须先影子输出并保持旧消费契约。[10]
- 按已确认需求，单票仓位彼此独立、不做组合归一；多只标的同时出现时，不能把全部建议机械相加为可执行组合，产品必须显式提示这一边界。

## 非显而易见的结论

**最危险的不是少一个因子，而是把不同时间和不同语义的“分”混成一个分。** 入选日五维分回答“当时是不是真龙”，T 日复盘分回答“今天是否仍值得准备”，T+1 反馈分回答“现在是否触发”，数据置信度回答“我有多少把握知道”。它们应能组合成决策，但不应互相冒充。[7][8][15][16]
